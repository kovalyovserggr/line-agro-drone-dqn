# WORKFLOW_CHECKLIST.md — регламент роботи над Статтею 3

Цей файл перечитується на початку КОЖНОЇ сесії роботи (людиною й асистентом).
Наприкінці сесії асистент звітує, які пункти виконано і які файли оновлено.
Правила взято з досвіду Статті 2 (GA маніпулятора) та Статті 1 (D1-D19).

## A. Початок сесії
- [ ] Перечитати цей файл, `A3_DECISIONS.md` (останні записи) і `STATE_ACTION_SPEC.md`.
- [ ] Перевірити поточну гілку (`article3-dqn`) і чи немає незакомічених змін від попередньої сесії (`git status`).
- [ ] Звірити, чи не змінювались файли в репо поза сесією (дата модифікації) — якщо так, працювати від нової версії.

## B. Будь-яка зміна моделі чи коду
- [ ] Рішення спершу записується в `A3_DECISIONS.md` (контекст → рішення → наслідки), потім код.
- [ ] Рішення, прийняте асистентом без підтвердження автора, позначається `СТАТУС: ПРОПОНУЄТЬСЯ` і не вважається прийнятим.
- [ ] Записи не редагуються заднім числом: перегляд рішення = новий запис із посиланням на попередній.
- [ ] Після зміни коду — запуск тестів відтворюваності (той самий seed → той самий результат).

## C. Перед кожною офіційною серією запусків
- [ ] Усі зміни закомічені; поставлено git-тег (`a3-vX.Y-<суть>`).
- [ ] У `experiments/article3/runs_index.md` додано рядок: run_id, тег, повна команда, seed-и, параметри.
- [ ] Мінімум 3 seed агента; N ≥ 20 seed оцінювання на кожну точку; seed навчання і тестування НЕ перетинаються.
- [ ] Конфіг серії записується в лог самого прогону (не покладатися на значення за замовчуванням — урок Статті 2).
- [ ] Бейслайни налаштовуються на навчальних seed, оцінюються на тестових; бюджет налаштування задокументовано.

## D. Після серії
- [ ] Сирі дані збережено в `experiments/article3/raw/` (CSV — у git; великі JSONL-журнали подій — стиснуті, у Zenodo-архів, у git лише хеш і шлях).
- [ ] Запис у `RESULTS_LOG` (наратив, ключові числа, статистика, висновок).
- [ ] Кожне число, що піде в текст, звірено з сирими даними скриптом, а не вручну.

## E. Рисунки і текст
- [ ] Рисунки будуються ЛИШЕ скриптами з сирих даних; кожен рисунок записано в `FIGURE_MANIFEST` (скрипт, дані, тег).
- [ ] Нумерація рисунків/таблиць у маніфесті збігається з порядком появи в тексті.
- [ ] Текст пишемо після заморожування результатів. Літературу звіряємо за першоджерелами (DOI, автори, рік), без нерецензованих препринтів.
- [ ] Параметри без джерела позначаються як «припущення» з діапазоном для аналізу чутливості.

## F. Кінець сесії
- [ ] Звіт асистента: що зроблено, які файли змінено, які рішення чекають підтвердження автора.
- [ ] Команди git для коміту (і тегу, якщо потрібно) — автор виконує сам.
